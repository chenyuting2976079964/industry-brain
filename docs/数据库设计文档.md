# 企开得胜数据库设计文档 v2\.1

# 一、文档概述

本文档是**企开得胜 MVP 版本**的数据库设计文档，包含完整的 ER 实体关系图、物理结构总览和建表语句。目标受众为后端开发工程师和数据库管理员。

技术选型：**MySQL 8\.0 \+ InnoDB**，字符集 **utf8mb4**。共 22 张表，按依赖关系分为 7 个批次。多数据源架构中 MySQL 作为唯一真相来源（Single Source of Truth），ES / Neo4j / Redis 通过 Canal binlog 准实时同步。

核心设计原则：

- 产业链节点采用双模结构：parent\_id 表达简化层级，chain\_node\_link 表达实际有向图（DAG）供需关系

- 企业名匹配通过 enterprise\_alias 别名表桥接

- 诊断算法采用绝对数量阈值法，不依赖外部统计指标

- 所有关联表严格外键约束（FOREIGN KEY \+ ON DELETE 策略）

- 枚举字段使用 CHECK 约束，防止脏数据写入

- 所有核心业务表均支持软删除（is\_deleted \+ deleted\_at）

# 四、建表顺序

按外键依赖排序，建表必须严格按以下顺序执行：

1. **第 1 批：基础配置** → region → industrial_park → industry_chain → chain_node → chain_node_link

2. **第 2 批：用户模块** → user → user_token

3. **第 3 批：核心主数据** → enterprise → enterprise_alias → patent → enterprise_tag → enterprise_advantage → enterprise_evaluation

4. **第 4 批：关联映射** → enterprise_node → patent_node

5. **第 5 批：业务计算** → node_diagnosis → investment_recommendation → alert

6. **第 6 批：运维审计** → attachment → report → operation_log → data_sync_log

其中 **第 3 批**（enterprise / patent 等）数据量最大，建议先建表 → 导入数据 → 再建索引和 FK，或使用 LOAD DATA INFILE 批量导入。外键约束可在导入完成后统一添加以提高导入速度。

# 五、完整建表语句

## 第一批：基础配置表

本批包含区域、产业链定义、节点及节点间关系，是全部业务数据的底座。产业链节点采用**双模结构**——parent\_id 表达简化层级归属，chain\_node\_link 表达实际有向图（DAG）供需连线。

### 表1：区域表（region）陈涛

```sql
CREATE TABLE region (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '区域ID',
    name            VARCHAR(100) NOT NULL COMMENT '区域名称',
    code            VARCHAR(50) NOT NULL UNIQUE COMMENT '区域编码（GB/T 2260 国标）',
    parent_id       BIGINT DEFAULT NULL COMMENT '上级区域ID',
    is_deleted      TINYINT DEFAULT 0 COMMENT '软删除：0正常/1已删除',
    deleted_at      DATETIME DEFAULT NULL COMMENT '删除时间',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_parent_id (parent_id),
    CONSTRAINT fk_region_parent FOREIGN KEY (parent_id) REFERENCES region(id)
        ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='区域表';
```

### 表5：节点关系表（chain\_node\_link）🆕

```sql
CREATE TABLE chain_node_link (

    source_node_id      BIGINT NOT NULL COMMENT '源节点ID',
    target_node_id      BIGINT NOT NULL COMMENT '目标节点ID',
    relation_type       VARCHAR(20) NOT NULL COMMENT '关系类型：SUPPLIES/DEMANDS',
```

```sql
CREATE TABLE user (
```

```sql
CREATE TABLE node_diagnosis (

    diagnosis_tag            VARCHAR(10) NOT NULL COMMENT '诊断标签',
```

# 七、Neo4j 图数据库约束与索引

以下为 Neo4j Community 版本实际使用的初始化语句。因 Community 版本限制，全文索引（FULLTEXT INDEX）和向量索引（VECTOR INDEX）已移除（仅 Enterprise 支持）。实际部署版本为 neo4j:5\.15\.0\-community。在 MySQL 建表完成后、种子数据导入前执行。

## 7\.1 节点约束与索引

```cypher
// ==================== 节点唯一约束 ====================

// 产业链
CREATE CONSTRAINT IF NOT EXISTS FOR (c:IndustryChain) REQUIRE c.chainId IS UNIQUE;

// 产业链节点
CREATE CONSTRAINT IF NOT EXISTS FOR (n:ChainNode) REQUIRE n.nodeId IS UNIQUE;

// 专利
CREATE CONSTRAINT IF NOT EXISTS FOR (p:Patent) REQUIRE p.patentId IS UNIQUE;

// 企业
CREATE CONSTRAINT IF NOT EXISTS FOR (e:Enterprise) REQUIRE e.enterpriseId IS UNIQUE;

// 区域
CREATE CONSTRAINT IF NOT EXISTS FOR (r:Region) REQUIRE r.regionId IS UNIQUE;

// ==================== 属性索引（加速查询） ====================

// 按区域编码查询
CREATE INDEX IF NOT EXISTS FOR (c:IndustryChain) ON (c.regionCode);
CREATE INDEX IF NOT EXISTS FOR (e:Enterprise) ON (e.regionCode);
CREATE INDEX IF NOT EXISTS FOR (p:Patent) ON (p.regionCode);

// 按名称搜索
CREATE INDEX IF NOT EXISTS FOR (e:Enterprise) ON (e.name);
CREATE INDEX IF NOT EXISTS FOR (p:Patent) ON (p.patentNumber);

// 专利申请人字段搜索
CREATE INDEX IF NOT EXISTS FOR (p:Patent) ON (p.applicant);

// 诊断标签索引
CREATE INDEX IF NOT EXISTS FOR (n:ChainNode) ON (n.diagnosisTag);

// ==================== 全文索引（专利文本搜索） ====================

CREATE FULLTEXT INDEX patentFullText IF NOT EXISTS
FOR (p:Patent)
ON EACH [p.patentName, p.abstractText]
OPTIONS { indexConfig: { `fulltext.analyzer`: `standard` } };

// ==================== 向量索引（专利语义检索，384维） ====================

CREATE VECTOR INDEX patentEmbedding IF NOT EXISTS
FOR (p:Patent)
ON (p.embedding)
OPTIONS { indexConfig: {
  `vector.dimensions`: 384,
  `vector.similarity_function`: `cosine`
}};
```

## 7\.2 关系类型定义

|关系类型|方向|属性|说明|
|---|---|---|---|
|`HAS_NODE`|Chain → Node|—|产业链包含哪些节点|
|`SUPPLIES_TO`|Node → Node|—|上游节点供应到下游节点|
|`DEMANDS_FROM`|Node → Node|—|下游节点需求来自上游节点|
|`BELONGS_TO`|Patent → Node|confidence, matchType|专利归属到产业链节点（含置信度）|
|`OWNS`|Enterprise → Patent|ownershipType|企业持有专利|
|`CITES`|Patent → Patent|—|专利引用关系|
|`CO_INVESTS_WITH`|Enterprise ↔ Enterprise|sharedPatentCount|企业协同投资/联合申请专利|
|`LOCATED_IN`|Enterprise → Region|—|企业所在区域|
